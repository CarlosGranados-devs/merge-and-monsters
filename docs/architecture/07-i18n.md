# Internationalization

**Last updated**: 2025-01-27
**Version**: 0.1.0

---

## Setup

i18next is configured in `src/lib/i18n/index.ts`. React components access it via the `useTranslation` hook from `react-i18next`. All top-level strings use a single default namespace.

```typescript
// src/lib/i18n/index.ts
i18next
  .use(initReactI18next)
  .init({
    lng: detectLanguage(),   // from localStorage or navigator.language
    fallbackLng: 'en',
    resources: { en: { translation: en }, es: { translation: es } },
    interpolation: { escapeValue: false },
  });
```

## Locales

| File | Role |
|------|------|
| `src/lib/i18n/locales/en.json` | Source of truth. All keys defined here. |
| `src/lib/i18n/locales/es.json` | Spanish translation. Must have the same keys as `en.json`. |

Both files are updated in the same commit that introduces a new UI string.

## Language Detection

```typescript
function detectLanguage(): string {
  const stored = localStorage.getItem('m_and_m:locale');
  if (stored === 'en' || stored === 'es') return stored;
  const browser = navigator.language.slice(0, 2);
  return browser === 'es' ? 'es' : 'en';
}
```

The user can override via a UI toggle (future feature). The selection is persisted to `localStorage` under key `m_and_m:locale`.

---

## Rules

- No string literals in JSX. All visible text goes through `t()`.
- Dynamic values use i18next interpolation (`{{variable}}`), not string concatenation.
- Plurals use i18next plural suffixes (`_one`, `_other`) where needed.
- Both locale files are committed together when new keys are added.
